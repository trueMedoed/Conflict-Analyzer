# Conflict Analyzer

Мод-помощник для исследования миров Conflict в Arma Reforger. Планируется автоматически собирать таблицы групп ИИ, источников припасов, стартовых баз и точек появления машин по аналогии с `how-does-this-work/Arma-Reforger/Conflict/Constants`.

**Статус: целевые отчёты припасов / локаций и отдельная диагностика Workbench.** Проверен установленный `CTI_Campaign_HQC_Eden.ent` версии **1.8.0.13**. Новая команда отбирает только `SCR_CampaignSourceBaseComponent` и четыре нужных поля; [ревизия r0002](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/revisions/r0002/Supplies/Harbors.md) содержит отдельный `Harbors.json` и таблицу 18 источников с пополнением за цикл и интервалом в минутах. Полный анализ четырёх разделов, разрешение каталогов групп и сравнение версий ещё не готовы. План находится в [TODO.md](TODO.md).

Первый эксперимент нашёл **299 точек ИИ**, **181 ambient-точку машин**, **18 баз-источников припасов** и **8 кандидатов HQ**. Это настройки источников, а не число появившихся бойцов, машин или выбранных штабов. Подробности — [отчёт эксперимента](docs/experiments/HQC_Eden_1.8.0.13.md), запуск — [диагностика source](docs/SOURCE_DIAGNOSTICS.md).

Для аэропорта `SP_A_EveronAirport` проверены [вместимость и состав хранилищ в r0003](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/revisions/r0003/Supplies/StorageCapacity.md): 3 контейнера по 1000 и 2 по 500, всего **4000 припасов**. Отдельная команда сохраняет физические контейнеры и исключает виртуальные представления из суммы. Это исследование одной базы; инструкция и границы результата — [STORAGE_CAPACITY.md](docs/STORAGE_CAPACITY.md).

[Harbors](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/Supplies/OtherContainers.md#harbors) показан отдельной категорией из **18 баз**, независимо от соседних подписей карты. Сохранены пополнение за цикл, интервал в минутах и вместимость: **49** физических контейнеров, **40500** известного подытога, **3** полные вместимости unknown. Полные исходные данные — [r0004](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/revisions/r0004/Supplies/Harbors.json); даты дохода / вместимости сохраняются раздельно.

[OtherContainers](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/Supplies/OtherContainers.md) сохраняет **124** корневых родителя / **568** физических контейнеров / **190700** настроенной вместимости. В r0033: **35** родителей у контрольных точек, **49** у складов CampaignRemnantsSupplyDepot, **13** у городов / деревень, **23** у остальных локаций, **4** нераспознанных — StartingPos21 и три хранилища за радиусом склада. [Полный исходный JSON r0006](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/revisions/r0006/Supplies/OtherContainers.json) сохраняет индивидуальные слоты; значения и исходные capture-даты сохранены.

[Справочник локаций](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/Locations.md) и таблица припасов используют общий [канонический граф r0033](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/revisions/r0037/Locations.json): **158 объектов**, **170 исходных именованных подписей**, **9 дополнительных маркеров складов**, **45 видимых групп**. Семь прежних объединений подписей с контрольными точками сохранены; группы справочника не меняют source-иерархию мира.

Цель Locations — сверять группировку объектов у разрешённых локаций в Workbench и находить разбросанные объекты. В заголовке каждой группы указаны координаты локации; таблица содержит объект, расстояние и его собственные координаты. В конце Locations находится раздел «Нераспознанные» для ручного изучения оставшихся объектов. Приоритеты начинаются с меток складов и хранилищ в 100 м от них; группы справочника не устанавливают фактическую принадлежность сущностей в мире.

Архитектура [таблицы припасов](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/Supplies/OtherContainers.md), r0033: **склады припасов → контрольные точки → Harbors → города / деревни → остальные объекты → нераспознанные**. Сначала маркеру склада подбирается локация в 350 м, затем собираются хранилища в 100 м от его позиции по X/Z. Назначенные ID исключаются из всех следующих этапов. Остаток проходит прежние source-проверки КП / Harbors, подбор подписей и объединение групп с КП. У каждой КП показано собственное хранилище командного пункта: 1000 вместимости, состав для 5 / 6 контейнеров; прежние компонентные 250 / 500 сохранены в JSON. [Алгоритм / запуск](docs/SUPPLY_PRIORITY.md).

По указанию пользователя **Provins связан с Transformer Station**: все 5 объектов перенесены к контрольной точке, отдельный нижний раздел убран. Расстояние между якорями — 231.365 м; [явное правило](tools/config/ControlPointMapLinks.json) действует только для этой пары / мира / версии игры.

У каждой контрольной точки командный пункт и остальные хранилища показаны в одной таблице; командный пункт идёт первым, с `1000 / 0` и расстоянием `0` до корня на позиции КП. Начальные припасы 0 подтверждены для действия префаба; запас всей базы после отложенной инициализации миссии отдельно не измерен. Таблицы контейнеров показывают сначала **Вместимость / Изначально** (например, `2000 / 2000`), затем **Состав, припасы** (`2 × 1000`), координаты и расстояние. Source ID и отдельный счётчик контейнеров остаются в JSON.

[Склады припасов](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/Supplies/OtherContainers.md#склады-припасов): **9** маркеров и **49** родителей / **266** физических контейнеров / **69600** вместимости. Все девять имеют списки. У склада Régina теперь **5 хранилищ / 31 контейнер / 7100 припасов**; эти объекты исключены из контрольной точки Régina. [Целевой экспорт и правила](docs/SUPPLY_DEPOTS.md).

Harbors собран в одну таблицу: **название → вместимость → состав контейнеров → интервал пополнения → количество за цикл → координаты**. Все 18 баз представлены строками; вместо повторных заголовков и пояснений состав показан как `2 × 500 + 3 × 1000`. Три неизвестных вместимости / состава остаются unknown.

В разделе складов сначала показана **локация → маркер склада → контейнеры**. Название выбирается в 350 м: сначала город / деревня / поселение, затем другая разрешённая подпись, ближайшая в выбранном этапе. **7** маркеров связаны с локациями; **2** остаются в отдельном разделе «Без привязки к локации» со своими контейнерами. Исходные значения и названия локаций сохранены; контейнерные назначения пересчитаны по новому приоритету и радиусу 100 м. [Правила](docs/SUPPLY_DEPOTS.md).

Координаты в актуальных таблицах и заголовках округлены до **трёх знаков после точки**, в формате X Y Z через пробел для вставки в Workbench: например, `4943.125 28.594 11793.299`. Полная исходная точность, расчёт расстояний и группировка сохраняются в JSON.

В разделе складов показаны название / координаты локации и списки объектов с их собственными координатами. Координаты маркеров складов в Markdown не выводятся; полные позиции остаются в JSON. Списки и остатки сохраняются. Настройки компонентов маркеров также скрыты в Markdown; исходные значения остаются в JSON, исследование их влияния на игру отложено в TODO.

[Хранилище командного пункта КП](docs/experiments/CONTROL_POINT_STORAGE_1.8.0.13.md) теперь показано у всех семи контрольных точек: **1000** вместимости; **5 контейнеров: 5 × 200**, **6 контейнеров: 5 × 166 + 1 × 170**. Workbench подтвердил FIA=5 / US=6 / USSR=6 физических слотов, виртуальный представитель исключён. Состав рассчитан по конфигу / коду действия; [канонические варианты](snapshots/1.8.0.13/worlds/CTI_Campaign_HQC_Eden/revisions/r0037/Supplies/ControlPointStorage.json). Выбранная фракция и полная игровая ресурсная сеть отдельно не определялись.

## Что планируется извлекать

| Раздел | Данные |
| --- | --- |
| Группы ИИ | Точки спавна, фракция, тип и prefab группы, состав и число бойцов, число групп по типам, вероятность появления, координаты |
| Припасы | Число точек и отдельных хранилищ, категория точки, начальное количество, вместимость, количество и интервал пополнения |
| Стартовые базы | Все кандидаты HQ и условия выбора, фракция, мировая позиция, стартовые припасы базы, количество и интервал их генерации |
| Машины | Точки спавна, позиция и направление, категория и допустимые варианты машин, ограничения выбора, настройки появления и повторного спавна |

Для каждого результата нужно показывать источник. Настройки миссии описывают возможный спавн; фактическое количество объектов во время игры может зависеть от выбора HQ, вероятностей и условий выполнения.

## Архив данных и сравнения

Утверждённая структура: **версия игры → сценарий мира → данные и таблицы**. Постоянные снимки хранятся в `snapshots/<game-version>/worlds/<scenario-key>/`, отчёты сравнения — отдельно в `changes/<old-version>_to_<new-version>/`. Оба каталога находятся в корне репозитория и сохраняются в Git; временная подготовка выгрузок выполняется в игнорируемом `exports/`.

Первый снимок **1.8.0.13 / CTI_Campaign_HQC_Eden / r0001** содержит манифест версии, метаданные сценария, нормализованный `data.json`, индекс `Supplies.md` и таблицу `Supplies/Harbors.md`. Выбраны все 18 баз с `SCR_CampaignSourceBaseComponent`: 17 портов и аэропорт. Вместимость, игровые названия локаций, ИИ, HQ и машины ещё не нормализованы; их отсутствие не означает нулевые итоги.

`tools/Convert-SupplySources.ps1` преобразует нативную диагностику в частичный `data.json` и строит Markdown из сохранённого JSON. Он отказывается писать в существующий каталог. Подготовка выполняется в `exports/`, перенос проверенной ревизии в архив и обновление манифеста пока ручные. Исходные секунды сохраняются, минуты вычисляются делением на 60. Сравнение снимков ещё не реализовано. Подробности и команда запуска — [docs/DATA_LAYOUT.md](docs/DATA_LAYOUT.md), [архив снимков](snapshots/README.md) и [каталог сравнений](changes/README.md).

В **r0002** реализован первый раздел [алгоритма экспорта](docs/EXPORT_ALGORITHM.md): базам-источникам соответствует `Supplies/Harbors.json`, Markdown строится из него, `data.json` содержит только индекс разделов. Нативный JSON целевой команды занимает **16 420 байт** и содержит 18 записей вместо 3 153 в широкой диагностике. Он сохраняет исходный мир каждой subscene, включая Eden; другие компоненты и поля не выгружаются. Подготовка ревизии выполняется `tools/New-SupplySourcesReport.ps1` без обязательного широкого дампа. Команда и пример запуска — [docs/SUPPLY_SOURCES.md](docs/SUPPLY_SOURCES.md). Перенос в архив и обновление манифеста пока ручные; `r0001` остаётся в прежнем формате.

## Открытие в Workbench

1. Запустите установленную Arma Reforger Tools / Workbench и добавьте существующий проект `ME_Conflict_Analyzer/addon.gproj` через список проектов.
2. Убедитесь, что доступен addon базовой игры, и дождитесь сканирования ресурсов.
3. Проверьте журнал на ошибки загрузки и зависимостей. Фактические результаты проверок записаны в [docs/VALIDATION.md](docs/VALIDATION.md).
4. Откройте мир Conflict и выполните `Plugins → [ME] Conflict Analyzer → Diagnostics → Export world source diagnostics`. Команда читает текущее состояние редактора; для воспроизводимого результата используйте сохранённый мир в отдельном экземпляре Workbench.

Каркас и диагностический скрипт проверены Workbench **1.8.0.13** 05.10.2026. В успешном прогоне HQC Everon проверены 3 153 позиции: максимальное расхождение с объектами редактора — **0,000244 м**, несовпадений выше порога 0,02 м нет. Учтены повёрнутые родители и высота относительно рельефа; отдельная проверка родителя с масштабом, отличным от единицы, ещё нужна.

Автоматический эксперимент использовал JSON в журнале и проверяемую сборку файла скриптом `tools/Convert-DiagnosticsLog.ps1`. Прямая файловая выгрузка из меню может потребовать разрешения FileIO в Workbench и остаётся для интерактивной проверки. При автоматическом выходе есть сообщения Resource leaks для UI-ресурсов; они воспроизводятся и на базовой игре. Подробности — в [docs/VALIDATION.md](docs/VALIDATION.md).

В этой локальной установке для проверки потребовался параметр `-addonsDir` с каталогом `D:\SteamLibrary\steamapps\common\Arma Reforger\addons`: без него Workbench не находил GUID базовой игры. При обычном открытии добавьте проект базовой игры в список Workbench, если зависимость не найдена. У другой установки путь будет отличаться.

## Исходные материалы и ограничения

Изучены локальные `AI-Group-Types.md`, `AI-Spawn-Points.md`, `Locations.md`, `SupplyStorages.md` и `Names.md` в каталоге `Conflict/Constants`. Это ориентиры для формы отчёта, а не гарантированные значения для текущей версии игры. `Locations.md` и `SupplyStorages.md` указывают версию `1.7.0.49`.

Локальный пример `OriginalWorlds/Everon - HQC/1.7.0.33/worlds/MP/CTI_Campaign_HQC_Eden.ent` содержит ссылку `SubScene → Parent` на Eden; настройки сцены находятся в соседнем `CTI_Campaign_HQC_Eden_Layers/default.layer`. В слое есть вложенные сущности, ссылки на prefab и локальные переопределения. Поэтому одного чтения `.ent` недостаточно для полного отчёта.

Структура слоёв описана также в официальной [документации SCR_WorldFilesHelper](https://community.bistudio.com/wikidata/external-data/arma-reforger/ArmaReforgerScriptAPIPublic/interfaceSCR__WorldFilesHelper.html). Возможности будущего плагина нужно сверить с API установленной версии Workbench.

Широкая диагностика читает доступные примитивные значения и признак override; отдельная команда вместимости раскрывает только нужный вложенный список m_aContainers. Полная цепочка происхождения, другие объектные конфиги и runtime-связи ещё не разрешены. Для source base количество дохода отделено от вместимости, интервал представлен в секундах и минутах. Для трёх баз нужно разрешить связь с отдельно расположенными контейнерами; условия дохода, единицы других настроек и runtime-принадлежность складов остаются для исследования. Неполные данные обозначаются явно. Runtime-диагностика, вооружение бойцов и стоимость строительства остаются отдельными возможными расширениями.

## Проверка начального запаса КП

В отдельном [игровом эксперименте HQC Everon 1.8.0.13](docs/experiments/CONTROL_POINT_RUNTIME_1.8.0.13.md) измерены семь стартовых КП FIA: после инициализации собственное хранилище каждого содержит 0 из 1000 припасов. Общая сеть базы содержит припасы и учтена отдельно. Один снимок получен в штатном сценарии, три повторных — при прямом запуске мира. Это исследование, автоматическая runtime-команда пока не реализована.

Примечание о переносе объектов подписей карты показано один раз в начале раздела «Контрольные точки» текущих таблиц. Текущие данные относятся к r0037.

У складов без привязки к локации над каждой таблицей показаны координаты маркера: X Y Z, три знака после точки.
