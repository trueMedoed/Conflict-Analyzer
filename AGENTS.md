## Назначение и текущий этап

Помощник для исследования миров Conflict в Arma Reforger. Пользователь утвердил название **Conflict Analyzer** и режим **помощника Workbench**: читать выбранный мир и формировать отчёт по аналогии с таблицами `Conflict/Constants`.

Реализованы широкая диагностика editor source и отдельный целевой экспорт баз-источников припасов, проверенные на HQC Everon 1.8.0.13. Объём задачи и критерии готовности находятся в `TODO.md`; запуск целевой команды — в `docs/SUPPLY_SOURCES.md`, диагностики — в `docs/SOURCE_DIAGNOSTICS.md`.

## Реализация

- Не ограничивайтесь текстом `.ent`: учитывайте слои, родительский мир, prefab, конфиги и переопределения. Недоступные зависимости обозначайте явно.
- Следуйте утверждённому [алгоритму отбора и экспорта](docs/EXPORT_ALGORITHM.md): читать зависимости, включая Eden, но сохранять только объекты нужных разделов и явный список полей. Префиксы классов `SCR_Campaign` / `SCR_Ambient` / `SCR_Resource` не являются достаточным фильтром обычного отчёта; не исключайте родительский мир целиком.
- Обычный экспорт должен сразу распределять нормализованные записи по JSON рядом с соответствующими Markdown-таблицами; общий `data.json` нового формата — индекс, без дублирования записей. Широкий дамп всех доступных полей оставляйте отдельным явно выбранным режимом диагностики.
- Не подставляйте значения из старых таблиц вместо данных анализируемой версии мира. Для каждого значения сохраняйте источник и способ получения.
- Различайте количество точек спавна, групп и бойцов; кандидатов HQ и реально выбранную базу; начальные припасы, вместимость и доход.
- Вместимость выбранной базы раскрывайте по иерархии база → хранилище → физический контейнер через `SCR_ResourceComponent.m_aContainers`. Для каждого сохраняйте `m_fResourceValueMax` отдельно от `m_fResourceValueCurrent`, ID, prefab и происхождение. Суммируйте уникальные физические слоты SUPPLIES; виртуальные `SCR_ResourceContainerVirtual` сохраняйте для проверки и не прибавляйте повторно. Не объявляйте сумму вложенных контейнеров полной runtime-вместимостью базы без проверки ресурсной сети.
- Не выдавайте локальные координаты дочернего объекта за мировые. Учитывайте преобразования родителей.
- Отсутствующее или неразрешённое значение означает `unknown`, а не ноль. Частичный результат обозначайте как `partial`.
- Анализ по умолчанию только читает данные. Экспорт должен идти в отдельный каталог, без сохранения изменений в исходный мир.
- Утверждённая структура архива: `snapshots/<game-version>/worlds/<scenario-key>/`; сравнения хранятся отдельно в `changes/<old-version>_to_<new-version>/`. Эти каталоги находятся вне addon и сохраняются в Git; временные выгрузки идут в игнорируемый `exports/`.
- Следуйте `docs/DATA_LAYOUT.md`: JSON служит источником для генерируемых Markdown-таблиц, сравнение опирается на стабильные идентификаторы и метаданные версий. Сохраняйте опубликованные снимки и явно обозначайте неполные данные.
- Сохраняйте только фактически собранные и проверенные данные; не выдавайте примерные версии и пустые JSON за снимки. Пользователь утвердил поэтапное наполнение архива: неполные разделы обозначайте `not_analyzed`, весь снимок — `partial`.
- JSON по отчётам реализован для баз-источников, их вложенных хранилищ и остальных физических контейнеров с припасами. Остальные разделы добавляйте по тому же алгоритму в новые ревизии; исходный r0001 со schemaVersion 1 сохраняйте в `revisions/r0001/` без изменения содержания. Корневой `Supplies/Harbors.md` — актуальная таблица с ссылками на канонические JSON текущей ревизии; корневые `data.json` / `world.json` сохраняют прежний формат r0001. ## Документация и проверки

## Публикация на GitHub

- По указанию пользователя после каждого завершённого набора изменений напоминать в итоговом сообщении о публикации на GitHub и явно указывать, что ещё осталось локально.
- Проверки и локальные коммиты можно выполнять в рамках текущей задачи. Перед коммитом сохраняются правила просмотра diff и проверки списка файлов выше.
- Выполнять `git push`, создавать PR или публиковать GitHub Release только по явной команде пользователя для соответствующего набора изменений. Напоминание не является запросом обязательного подтверждения: дождаться отдельного указания о публикации.
- Ранее выполненная просьба опубликовать изменения не даёт постоянного разрешения на публикацию следующих изменений. По умолчанию новые изменения и коммиты остаются локальными.
